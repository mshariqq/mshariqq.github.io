What is HMS SaaS?

HMS SaaS is a Laravel 12 hospital management platform built for multi-tenancy. A super admin manages hospitals and subscription plans, while each hospital gets its own landing page and admin panel covering appointments, OPD and IPD, billing, pharmacy, laboratory, radiology, blood bank, payroll and reports.

Unlike a single-clinic HMS, this is designed to be sold as a service: hospitals register, subscribe through Stripe or PayPal, and their data stays separated. That makes server sizing and subdomain or domain mapping part of the installation, not an afterthought.

It is a serious healthcare product with serious dependencies. SMS needs Twilio, live consultations need Zoom, and the platform ships with a limited set of currencies and languages. I check those before you promise a client something the system cannot do.

How a HMS SaaS setup works

01
Server sizing
Multi-tenant healthcare needs more than a small shared plan. I confirm PHP 8.2+, MySQL, Composer, disk and memory, then plan subdomains or custom domains for hospitals.
02
Install and database
Upload the Laravel app, run Composer, create the database and migrate and seed. I set the app URL, storage link and permissions, then create the super admin.
03
Subscriptions and mail
Configure Stripe or PayPal, plan pricing and trial rules, plus SMTP and Twilio for SMS. I test a hospital signup and a subscription charge in sandbox mode first.
04
Hospital onboarding
Create a test hospital, its admin user, departments, doctors, schedules and charges. This proves the tenant isolation works before real patient data exists.
05
Clinical modules
Set up pharmacy stock, lab and radiology tests, bed types and billing rules. I keep the first configuration minimal so staff are not overwhelmed by unused modules.
06
Zoom, reports and handover
Connect Zoom for live consultations, check the main reports, and train the hospital admin on the daily OPD flow. Compliance and retention policies remain the hospital's responsibility.

Is it really multi-tenant? +
Yes. A super admin manages hospitals and each hospital has its own panel and landing page. I verify data separation with a test hospital during setup.
Does it include a mobile app? +
The Codecanyon listing advertises a mobile app, but packaging varies by release. I check the files you actually own before quoting app work.
Do I need Twilio and Zoom? +
Twilio is needed for SMS and Zoom for live consultations. Both are third-party accounts with their own usage costs, so I connect them only if you need those features.
Can I run this on shared hosting? +
Not realistically for multiple hospitals. Plan a VPS or cloud server with enough memory, backups and HTTPS.
How long does setup take? +
A single hospital on one server is usually a day or two. Subscriptions, SMS, Zoom, billing rules and staff roles push it to several days.
