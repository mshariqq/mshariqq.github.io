What is FoodTiger?

FoodTiger is a self-hosted multi-restaurant food ordering and delivery platform. A Laravel admin registers restaurants and drivers, assigns orders and watches analytics, while each restaurant owner manages their own menu and accepts or rejects orders from a panel.

Each restaurant is served from its own subdomain, which keeps branding separate and is how the platform separates storefronts. That also means wildcard DNS and SSL need to be configured properly, which is a frequent stumbling block.

The customer, driver and vendor mobile apps are separate purchases built with React Native and Expo. Budget for them on top of the backend, plus the Expo/Node tooling needed to build and publish the apps.

How a FoodTiger setup works

01
Backend install
Standard Laravel deployment: PHP 8.2+ (v4.0 and later), MySQL, composer, environment file, migrations and admin account.
02
Wildcard subdomains and SSL
Because every restaurant gets a subdomain, I configure wildcard DNS and a wildcard SSL certificate so new restaurants work without manual certificate requests.
03
Maps, mail and payments
Google Maps API keys for delivery addresses and distance, SMTP for order emails, and the payment gateways you intend to accept.
04
Apps and Firebase
Build and configure the React Native apps: point them at your API, set Firebase Cloud Messaging for push, maps keys and app identity, then produce signed builds.
05
Store publishing
Prepare the app store listings, icons and screenshots, and push builds to Google Play and the App Store.
06
End-to-end test
Place a live order from the customer app through to the driver app and confirm the restaurant panel sees it — before you take real customers.
